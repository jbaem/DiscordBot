# 🤖 디스코드 방 관리 봇 (Discord Management Bot)

디스코드 서버의 **임시 음성 채널(Join-to-Create) 자동 생성 및 삭제**, **채널 잠금**, **신규 멤버 환영/퇴장 알림 및 자동 역할 부여**를 담당하는 올인원 방 관리 봇입니다.

---

## 🔐 명령어 권한 구분

모든 명령어는 **한글 슬래시 명령어**로 제공되며 두 등급으로 나뉩니다. 관리자 전용 명령어는 권한이 없는 멤버의 명령어 목록에서 **숨겨지며**, 서버 설정에서 권한을 바꿔 노출되더라도 봇이 실행 전에 한 번 더 검사해 거부합니다.

| 등급 | 사용 조건 | 명령어 |
|---|---|---|
| 👑 **관리자 전용** | 서버 소유자, 관리자(Administrator) 권한, 또는 서버 관리(Manage Server) 권한 | `/연결 채널`, `/관리` (채널·역할), `/문구`, `/테스트`, `/자동역할`, `/역할`, `/백업`, `/핑` |
| 👥 **모든 멤버** | 제한 없음 (`/정보` 로 다른 유저를 조회하는 것은 관리자만 가능) | `/정보`, `/도움말` |

`/도움말` 은 사용자의 등급에 맞춰 사용할 수 있는 명령어만 보여 줍니다. `분류` 를 고르면 해당 분류만 보이며, 고를 수 있는 분류 목록도 등급에 따라 다릅니다. 관리자 역할(예: `메타몽`, `덩쿠림보`)에는 **서버 관리** 권한을 켜 두어야 관리자 명령어가 보입니다.

---

## 🌟 주요 기능

### 1. 🔗 채널 연결 (`/연결 채널`)
기능별 채널을 한 명령어로 연결·해제합니다. 연결하지 않은 기능은 비활성화 상태입니다.
- `/연결 채널 입장알림 <채널>` : 신규 멤버 환영 메시지를 보낼 텍스트 채널
- `/연결 채널 퇴장알림 <채널>` : 멤버 퇴장 알림을 보낼 텍스트 채널
- `/연결 채널 닉네임로그 <채널>` : 닉네임 변경 로그를 기록할 텍스트 채널
- `/연결 채널 음성생성 <채널>` : 접속 시 개인 통화방이 생성되는 음성 채널 (Join-to-Create 트리거)
- `/연결 채널 역할패널 <채널>` : 이모지 역할 패널을 띄울 텍스트 채널 (패널 1개만 유지, 연결하면 바로 게시)
- `/연결 채널 확인` : 연결된 채널 전체 확인
- `/연결 채널 해제 <기능>` : 특정 기능의 채널 연결 해제(비활성화)
- 슬래시 명령어로 연결하지 않은 서버는 `.env` 의 `WELCOME_CHANNEL_ID`, `LEAVE_CHANNEL_ID`, `JOIN_TO_CREATE_CHANNEL_ID` 를 폴백으로 사용합니다. `/연결 채널 해제` 로 끈 기능은 `.env` 에 값이 있어도 비활성화 상태를 유지합니다.

### 2. 👋 멤버 입장 / 퇴장 알림
- `/문구 입장 [문구]` : 입장 알림 문구 설정 (비우고 실행하면 현재 문구와 미리보기 확인)
- `/문구 퇴장 [문구]` : 퇴장 알림 문구 설정 (비우고 실행하면 현재 문구와 미리보기 확인)
  - 지원 변수: `{user}`, `{userName}`, `{userTag}`, `{userId}`, `{server}`, `{count}`, `{joinedAt}`, `{joinedAtRelative}`, `{createdAt}`, `{accountAge}`, `{joinCount}`, `{isRejoin}`
- `/테스트 입장알림` : 연결된 채널로 실제와 같은 형태의 입장 알림 테스트 전송
- `/테스트 퇴장알림` : 연결된 채널로 실제와 같은 형태의 퇴장 알림 테스트 전송
- 알림 임베드에는 **입장 시각**(입장 알림) 또는 **퇴장 시각과 함께한 기간**(퇴장 알림)이 표시됩니다. 멤버 수를 넣고 싶으면 문구에 `{count}` 변수를 사용하세요.
- **재입장(들낙) 멤버 자동 감지**: 서버별 멤버 입장/퇴장 이력을 기록하여 재입장 시 알림의 제목과 색상을 구분해 표시
- **닉네임 변경 로그**: 닉네임 로그 채널을 연결하면 멤버가 서버 닉네임을 바꿀 때마다 **변경 시각, 변경 전 이름, 변경 후 이름, 유저 정보**를 임베드로 기록

### 3. 🔊 임시 음성방 자동 생성 (Join-to-Create)
- 준비: 생성용 음성 채널(예: `➕ 클릭하여 통화방 생성`)을 직접 만든 뒤 `/연결 채널 음성생성 <채널>` 로 연결합니다. 생성용 채널의 인원 제한을 1명으로 두면 더 자연스럽게 동작합니다.
- `/문구 음성방서식 [서식]` : 생성될 방 이름 서식 변경 (예: `🔊 {userName}의 통화방`, 비우고 실행하면 현재 서식 확인)
- 생성 채널 연결 상태는 `/연결 채널 확인`, 기능 끄기는 `/연결 채널 해제 음성생성`
- 멤버가 생성 채널에 접속하면 **개인 음성방을 즉시 생성**하고 이동시키며, 마지막 멤버가 퇴장하면 **자동 삭제**됩니다.
- 방 이름 변경: 방을 만든 사람이 아니어도 **누구나 디스코드 채널 설정(채널 편집)에서 직접** 바꿀 수 있습니다. (별도 명령어 없음)
  - 봇이 임시 방마다 @everyone 에게 **채널 관리** 권한을 줍니다. 디스코드는 이름 변경만 따로 허용할 수 없어 인원 제한 변경과 방 삭제도 함께 가능합니다.
  - 방을 만든 사람은 추가로 음소거 / 스피커 끄기 / 멤버 이동 권한을 받습니다.

### 4. 🛡️ 서버 관리 (`/관리`)
- `/관리 채널 잠금` : 현재 채널 잠금
- `/관리 채널 잠금해제` : 현재 채널 잠금 해제
- `/관리 역할 부여 <역할> <유저> [유저2~5]` : 지정한 유저(최대 5명)에게 역할 부여
- `/관리 역할 회수 <역할> <유저> [유저2~5]` : 지정한 유저(최대 5명)에게서 역할 회수
  - 실행하는 사람에게 **역할 관리** 권한이 있어야 하고, 자신의 최상위 역할보다 **낮은** 역할만 다룰 수 있습니다. (서버 소유자는 예외)
  - 봇의 역할도 대상 역할보다 위에 있어야 하며, 봇/연동 전용 역할과 `@everyone` 은 다룰 수 없습니다.
  - 이미 가진 역할(부여) 또는 없는 역할(회수)은 건너뛰고, 결과는 실행한 사람에게만 표시됩니다.

### 5. 🎭 역할 자동화
- **자동 역할 (모든 구성원)** — 예: `포켓몬`
  - `/자동역할 설정 [이름]` : 구성원 역할을 새로 만들어 자동 역할로 지정하고, **기존 멤버 전체에게도 즉시 부여** (기본 이름: `포켓몬`)
  - `/자동역할 지정 <역할>` : 이미 있는 역할을 자동 역할로 지정
  - `/자동역할 일괄적용` : 현재 멤버(봇 제외) 전체에게 자동 역할 일괄 부여
  - `/자동역할 확인` : 설정 확인
  - `/자동역할 해제` : 비활성화
  - 새 멤버가 들어오면 자동으로 부여됩니다. 슬래시 명령어로 설정하지 않은 서버는 `.env` 의 `AUTO_ROLE_ID` 를 사용합니다.
- **이모지 반응 역할 (원하는 사람만)** — 예: 🎲 `겜블러`
  - 준비: `/연결 채널 역할패널 <채널>` 로 패널을 띄울 채널을 지정하면 바로 패널이 게시됩니다.
  - `/역할 추가 <역할> <이모지> [설명]` : 이모지와 역할 연결 (유니코드 또는 서버 커스텀 이모지). `설명` 은 패널과 `/도움말` 역할 안내에 표시됩니다.
  - `/역할 제거 <역할>` : 연결 해제
  - `/역할 패널 [제목] [설명]` : 패널 채널에 패널 게시 또는 갱신 (제목·설명을 비우면 기존 값 유지)
  - `/역할 갱신` : 패널을 현재 목록으로 갱신
  - `/역할 목록` : 등록된 이모지 역할과 패널 채널·메시지 확인
  - 멤버가 패널의 **이모지를 누르면 역할이 부여되고, 반응을 해제하면 역할이 제거**됩니다.
  - **패널은 서버에 항상 1개만** 유지됩니다.
    - 패널 채널에 이미 패널이 있으면 새로 올리지 않고 내용만 수정합니다.
    - 패널 채널을 바꾸면 이전 채널의 패널은 삭제하고 새 채널에 게시합니다. 예전에 중복으로 올라간 패널도 함께 정리합니다.
    - 패널 메시지를 지웠다면 다음 갱신 때 새로 게시합니다.
    - `/역할 추가` · `/역할 제거` 를 하면 패널이 자동으로 갱신되고, 목록에서 빠진 이모지의 반응도 정리됩니다.
    - `/연결 채널 해제 역할패널` 을 하면 게시된 패널을 삭제합니다.
  - 등록되지 않은 이모지 반응은 자동으로 정리되어 패널이 깔끔하게 유지됩니다.
- ⚠️ 두 기능 모두 **봇의 역할이 부여할 역할보다 위**에 있어야 하며, 관리자·서버 관리·역할 관리 등 위험 권한이 있는 역할과 봇/연동 전용 역할은 등록할 수 없습니다.
  - `@everyone 멘션` 권한은 **자동 역할에서는 허용**합니다(서버 방침). 새로 들어온 멤버도 바로 `@everyone`·`@here` 를 쓸 수 있다는 점에 유의하세요.
  - 이모지 역할은 누구나 패널에서 스스로 받는 역할이라 `@everyone 멘션` 권한이 있으면 등록할 수 없습니다.

### 6. 💾 설정 및 멤버 이력 백업 / 복원 (`/백업`)
- 봇은 설정과 멤버 이력, 활동 기록을 `data/` 폴더의 JSON 파일에 **자동 저장**합니다. 아래 명령어는 특정 시점의 상태를 따로 보관하고 되돌리기 위한 백업입니다.
- `/백업 내보내기` : 현재 서버의 설정(연결 채널, 문구, 역할 설정), 멤버 입장/퇴장·닉네임 이력, 활동 기록을 **봇 서버의 `backups/` 폴더에 자동 저장**하고, 같은 파일을 첨부로도 보내 줍니다 (본인에게만 표시)
  - 서버별로 최근 20개까지 보관하고, 넘으면 오래된 것부터 삭제합니다.
  - `backups/` 는 `data/` 와 같은 서버 디스크에 있으므로, 호스팅 서버 자체가 사라지는 경우에 대비해 첨부 파일도 내려받아 두세요.
- `/백업 불러오기 [백업] [파일] [모드] [강제]` : 백업으로 복원
  - 아무 옵션 없이 실행하면 **`backups/` 의 가장 최근 백업**을 자동으로 불러옵니다.
  - `백업` : 입력창에 뜨는 목록에서 특정 로컬 백업을 고를 수 있습니다.
  - `파일` : 내려받아 둔 백업 파일을 첨부하면 로컬 백업 대신 사용합니다.
  - 복원 직전 상태를 `before-restore` 백업으로 자동 저장하므로, 잘못 복원해도 그 백업을 골라 되돌릴 수 있습니다.
  - 모드 `병합`(기본): 기존 이력과 합치고 입장 횟수·메시지 수 등은 더 큰 값을 유지
  - 모드 `전체 교체`: 현재 이력을 지우고 백업 내용으로 덮어쓰기
  - 다른 서버에서 만든 백업은 `강제` 옵션을 켜야 적용되며, 현재 서버에 없는 채널 ID는 복원 후 안내됩니다.
- `/백업 목록` : `backups/` 에 저장된 이 서버의 백업 목록 확인 (시각은 한국 시간 기준)
- `/백업 미리보기` : `/백업 내보내기` 로 저장될 내용을 **파일을 만들지 않고** 미리 확인 (본인에게만 표시)
  - 설정(연결 채널·문구·자동 역할·이모지 역할), 멤버 이력(인원·재입장·닉네임 변경, 최근 입장 순), 활동 기록(메시지·음성 시간 합계, 활동 많은 순), 예상 파일 크기
- 호스팅 패널의 파일 관리자로 `backups/` 폴더에 백업 파일(`backup-<서버ID>-<날짜>-<시각>.json`)을 올려 두면 `/백업 불러오기` 목록에 나타납니다.
- ⚠️ 백업 파일에는 채널 ID와 멤버 ID, 입장 이력이 포함되므로 외부에 공유하지 마세요.

#### 🗄️ 채널 자동 백업 (`BACKUP_CHANNEL_ID`)
호스팅 서버가 재배포·재시작할 때 디스크(`data/`, `backups/`)를 지우더라도 데이터가 남도록, 백업 파일을 디스코드 채널에 자동으로 올리고 시작할 때 다시 불러옵니다.
- **시작 시**: 백업 채널에서 **봇이 올린 가장 최근 백업**을 그대로 불러오고(전체 교체) 채널에 `♻️ 시작 시 자동 복원` 안내를 남깁니다. 단, 디스크에 남아 있는 데이터가 그 백업보다 나중에 저장된 경우(강제 종료 등)에는 디스크 데이터를 유지합니다.
- **1시간마다 / 종료 시**: 마지막으로 올린 내용과 달라졌을 때만 `backup-<서버ID>-<날짜>-<시각>-auto.json` 을 올립니다. 종료 시에는 진행 중인 음성 시간도 정산해 포함합니다.
- 채널에는 서버별 최근 20개만 남기고 오래된 자동 백업 메시지는 삭제합니다 (다른 메시지는 건드리지 않음).
- 설정 방법
  1. 관리자만 볼 수 있는 **비공개 텍스트 채널**을 만듭니다 (예: `#봇-백업`). 멤버 ID와 이력이 올라가므로 반드시 비공개로 두세요.
  2. 봇에게 그 채널의 `채널 보기`, `메시지 보내기`, `파일 첨부`, `메시지 기록 보기` 권한을 줍니다.
  3. 채널 ID를 호스팅 패널의 환경 변수 `BACKUP_CHANNEL_ID` 에 넣습니다. 여러 서버에서 쓰면 쉼표로 구분합니다 (서버마다 채널 1개). 서버 설정은 `data/` 와 함께 지워질 수 있어 슬래시 명령어가 아닌 환경 변수로 지정합니다.
  4. 봇 시작 로그에 `[AutoBackup] ✅ N개 서버 자동 백업 사용 중` 이 보이면 정상입니다.
- 호스팅 패널이 봇을 강제로 끝내면(종료 신호 없이) 종료 시 백업은 실행되지 않으므로, 최대 1시간 사이의 변경이 빠질 수 있습니다.

### 7. 📊 유저 정보 및 활동 기록
- `/정보` : 내 정보 확인, 본인에게만 표시 (모든 멤버)
- `/정보 <유저>` : 다른 유저의 정보 조회 (**관리자 전용**, 관리자 본인에게만 표시)
- 활동은 봇이 켜져 있는 동안 자동으로 집계되어 `data/activity.json` 에 저장됩니다. (메시지 내용은 저장하지 않으며 `MESSAGE CONTENT INTENT` 가 필요하지 않습니다.)
  - 메시지 수: 서버에서 보낸 메시지 개수 (봇·웹훅·시스템 메시지 제외)
  - 음성 채널 시간: 음성 채널에 머문 시간 (서버 AFK 채널 제외)
  - 활동일: 메시지 또는 음성 활동이 있었던 날짜 수 (한국 시간 기준)
- 포인트(레벨) 기능은 없습니다.

### 8. ⚙️ 유틸리티
- `/핑` : 봇 응답 속도(레이턴시) 및 웹소켓 핑 측정
- `/도움말` : 볼 수 있는 **전체** 명령어 안내 (`/도움말 분류:전체` 와 같음)
- `/도움말 분류:<이름>` : 한 분류만 보기. 입력창 목록에 **내 권한으로 볼 수 있는 분류만** 표시됩니다.
  - 모든 멤버: `전체`, `정보`, `역할안내`
    - `역할안내` : 자동 역할(기본 멤버 역할)과 이모지 역할, 각 역할의 설명(`/역할 추가` 의 `설명`)을 보여 줍니다. 서버 설정을 그때그때 읽어 표시하므로 역할을 추가·제거하면 바로 반영됩니다. 관리자 역할(관리자·서버 관리 권한이 있는 역할)은 표시하지 않습니다.
  - 관리자: 위에 더해 `채널연결`, `관리`, `알림`, `음성방`, `역할`, `백업` (`관리` 에 채널 잠금과 역할 부여·회수 포함)
  - 분류가 많아져 한 메시지에 다 들어가지 않으면 여러 개로 나눠 보여 줍니다.

## 🛠️ 사전 준비 (디스코드 개발자 포털 설정)

봇을 구동하기 위해 디스코드 개발자 포털에서 봇을 등록해야 합니다.

### 1. 봇 생성 및 토큰 발급
1. [Discord Developer Portal](https://discord.com/developers/applications)에 접속하여 로그인합니다.
2. 우측 상단 **New Application** 클릭 후 이름을 지정하고 생성합니다.
3. 좌측 메뉴 **Bot** 클릭:
   - **Reset Token**을 눌러 봇 토큰을 복사합니다. (이 토큰이 `.env`의 `DISCORD_TOKEN`이 됩니다.)
   - ⚠️ **중요 (권한 허용)**: 스크롤을 내려 **Privileged Gateway Intents** 섹션에서 **SERVER MEMBERS INTENT** 스위치를 반드시 **ON**으로 켭니다. (환영 메시지 및 자동 역할을 위해 필수입니다.)

### 2. 애플리케이션 ID 확인
- 좌측 메뉴 **General Information**에서 **Application ID**를 복사합니다. (`.env`의 `CLIENT_ID`)

### 3. 디스코드에서 채널/서버/역할 ID 확인하는 법
1. 디스코드 앱 실행 -> **사용자 설정 (⚙️)** -> **고급** -> **개발자 모드**를 켭니다.
2. 이제 서버 이름, 텍스트 채널, 음성 채널, 역할을 **마우스 우클릭**하면 맨 아래에 **[ID 복사]** 버튼이 나타납니다.

### 4. 봇 서버에 초대하기
1. 좌측 메뉴 **OAuth2** -> **URL Generator** 클릭
2. **SCOPES**:
   - `bot`
   - `applications.commands` (슬래시 명령어 사용을 위해 필수)
3. **BOT PERMISSIONS**:
   - `Administrator` (가장 편리함) 또는 아래 권한 체크:
     - `Manage Channels` (채널 관리)
     - `Manage Roles` (역할 관리)
     - `Manage Messages` (메시지 관리)
     - `Move Members` (음성 채널 멤버 이동)
     - `Connect`, `Speak` (음성 접속/발언)
     - `Send Messages`, `Embed Links`, `Read Message History`
4. 하단에 생성된 URL을 복사하여 웹 브라우저 주소창에 넣고 자신의 서버에 초대합니다.

```env

AUTO_ROLE_ID=

# 1시간마다·종료 시 백업 파일을 이 채널에 올리고, 디스크 데이터가 지워진 채로 시작하면 여기서 불러옵니다.
BACKUP_CHANNEL_ID=
```

### 디스호스트 자동 배포 (GitHub Actions)
`main` 에 push(머지)되면 [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) 이 디스호스트 API 로 봇을 재배포합니다. Actions 탭에서 **Deploy to DisHost → Run workflow** 로 수동 실행도 됩니다.
1. 디스호스트 대시보드 → **설정 → API Keys** 에서 키 생성 (`dsh_live_...`)
2. GitHub 저장소 **Settings → Secrets and variables → Actions**
   - **Secrets** 탭 → `DISHOST_API_KEY` 에 키 저장 (코드나 채팅에 붙여 넣지 말 것)
   - (선택) **Variables** 탭 → `DISHOST_BOT_ID` 에 봇 ID 저장. 비우면 이 저장소와 연결된 봇을 자동으로 찾고, 못 찾으면 실행 로그에 봇 목록을 보여 줍니다.
3. 디스호스트 봇의 배포 브랜치(Git 브랜치)는 `main` 으로 둡니다.
